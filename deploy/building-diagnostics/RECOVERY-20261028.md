# Grafana recovery - 2026-10-28

## Incident

The Grafana instance on `10.0.0.22:3000` started with a newly created
`grafana.db`. The previous users, sessions, and the original network overview
dashboard were absent. Both Grafana and InfluxDB containers were subsequently
found removed while their bind-mounted data directories remained present.

## Recovery

- Recreated the existing `influxdb:2.7` and `grafana/grafana:10.2.2`
  containers from `/srv/sccc-ops/compose.yml` without replacing their bind
  mounts.
- Recovered `A - SCCC Network Overview` from the verified 2026-10-22 export.
- Initially restored the later 18-panel executive derivative, then corrected
  the recovery to the user's complete original 39-panel export after live
  comparison.
- Preserved UID `e7633483-9f63-4a1f-9d8e-84a5164954837`.
- Rebound all 39 dashboard query targets to the current provisioned datasource
  UID `bf0gpakqau6tcc`.
- Installed the dashboard as
  `/srv/sccc-ops/sccc-dashboards/sccc-network-overview.json`.

## Collector recovery

The container removal also deleted the locally built wireless collector image
and the prior Telegraf container/image. The source files and InfluxDB data were
still present.

- Rebuilt `sccc-wireless-metrics:1.1.2` from the surviving authoritative source
  under `/opt/sccc-wireless-metrics`.
- Confirmed the systemd timer is enabled and active; each completed run writes
  214 wireless metric series.
- Restored the Telegraf 1.30 container as a Compose override without changing
  the existing Grafana/InfluxDB Compose definition.
- Kept the production Telegraf configuration outside Git because it contains
  protected SNMP credentials. Its Influx token is supplied by
  `/etc/sccc-ops/stack.env`.
- Set `/srv/sccc-ops/telegraf/telegraf.conf` to owner `telegraf:telegraf` and
  mode `0600`. The official image entrypoint starts as root for capabilities,
  then drops to the Telegraf service identity.
